## Question

在用户再次确认具体维护窗口后，能否准备一套可恢复、可观测、不会同时控制同一音箱的验证环境，使后续候选比较有可信证据？

- 保留生产容器、数据库和音乐库；保存脱敏的运行版本、镜像、挂载、音频默认输出、设备管理者及恢复基线，敏感原件留在用户指定的安全位置。
- 确认真实设备独占、无竞争重连管理者；避免测试服务的 mDNS/自动发现把生产客户端转走，避免共享音频栈默认输出和 rescue 的隐式改动。
- 提供显式端点、受限网络、短音源、低音量、时间和声学记录方法；不以调大 lead-time 或关闭全局蓝牙代替输出准备。
- 提供逐步恢复清单与恢复验证；任何服务暂停、测试进程/容器启动、连接/断开或播放，都必须在当次确认的范围内。
- 若缺少权限、备份或恢复依据，记录阻塞，不绕过权限，不删除或重建生产容器。

这是为决策准备事实的任务，不是生产部署。此票有 HITL 维护窗口，不能在只读研究阶段认领执行。
