## Question

选定路线和控制范围后，能否用一个小 Interface、状态原型和故障注入测试，清楚表达播放意图、输出准备、可听时间线、取消、自然曲终与恢复，使实现不再散落同步补丁？

- 展示调用端必须知道的状态与顺序，把连接/路由/重试/释放藏在深模块内；保持控制端、播放权威和物理输出的责任分离。
- 明确稳定播放器身份、准备/失败状态、超时和旧结果失效，以及切歌共享输出使用权而不逐曲重连的语义。
- 自然曲终、主动停止、准备失败和连接断开须可区分；异步事件不能仅用缺少来源的布尔完成信号推进错误曲目。
- 若接入 Navidrome，说明 Track/newTrack、队列、错误/状态事件与 backend 注册所需改变；现有 WASM host 能发消息不等于已能注册播放 backend。
- 若保留 MA，验证准备钩子不会生成第二份权威时间线或队列；若增加界面，验证远端模式没有浏览器音频实际播放。
- 用可控时钟和依赖替身覆盖停止/切歌/重连竞争，另行标注只能靠硬件确认的声学和无线行为。
- 原型只为让用户评价 Interface 和行为；代码文件位置须另获批准，不把完整产品实现藏在原型票中。

调用 prototype 与 domain-modeling。关闭时记录已选 Interface、可验证的不变量、未覆盖领域和对最终实施方案的约束。
