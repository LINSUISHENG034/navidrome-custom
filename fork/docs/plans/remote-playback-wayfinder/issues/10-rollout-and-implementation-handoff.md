## Question

选型、控制范围和 Interface 清楚后，实现与投产方案是否已经没有必须先解决的决策，足以交给下一阶段执行？

- 在本票的最终 Answer 形成选定路线的实施顺序：版本锁定与环境、核心模块和注册点、输出生命周期、状态/鉴权、界面范围、测试、打包、灰度和旧路径退出。只为选定路线细化，不展开四套伪完整施工清单。
- 列出受影响模块、必要配置/持久化与依赖变更；新增/移动文件提前批准，优先扩展既有结构，避免复制实现。若有数据库迁移需求，另行批准备份/迁移/回退，不默许操作生产库。
- 给出可重复的软件测试、竞态/故障注入和硬件验收矩阵；涵盖首段/时延/失败截止、音量、自然结束、长暂停、闲置、取消、掉线、重启、控制端退出、单一队列和单一输出管理者。
- 给出脱敏日志/指标、错误分类与运维检查，以及版本升级兼容性验证；只读/模拟结果、真实设备结果和生产结果分别记录。
- 明确发布物、灰度开关与安全边界、维护窗口、音频路由/设备管理/配置恢复、成功与回滚触发条件；不得删除生产容器或默许其他 controller 继续控制同一输出。
- 若前端改变，说明嵌入构建、缓存和实际新版本验证；若没有原生界面改动，不为其引入无关测试或部署成本。
- 明确 Git 分支、signoff、限定路径提交、备份目标和上游贡献策略；现有仓库使用 master，不沿用 main 模板误推。
- 实施阶段仍需新的执行授权与实际操作确认；关闭本票代表计划可交接，不代表代码已完成或生产已验证。

调用 grilling 和 domain-modeling，与用户完成最终评审。若发现新 fog，先创建/链接新的决策票并阻塞本票，不以未决假设交付。
